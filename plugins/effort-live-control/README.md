# effort-live-control

Set each Claude Code sub-agent's reasoning effort per spawn, and let an opted-in agent's effort follow its own trouble while it works.

**The tag.** Make `[effort: low|medium|high|xhigh|max]` the first non-blank text of the Agent prompt, on one line (a markdown link `[effort: …](…)` is not a tag). The tag is removed before the sub-agent reads its prompt, and its own model requests run at that level. The tag also wins over a type definition's own `effort:` (a steered agent starts at the tag held within its floor and ceiling); `parentTag: ignore` pins the definition's. An untagged sub-agent is pinned to the effort of its first request, so a mid-run `/effort` change never reaches it; a pin clears when the sub-agent finishes. An unknown level refuses the spawn. Compaction forks and the agent panel's `agent_summary` request are not pinned (see the repository README).

**Live control.** An agent definition with `effortControl: on` (or nested `floor`, `ceiling`, `landing`, `judge`, `tripwires`, `struggleDecay`, `enabled`) is steered: its effort rises one step when its own test run fails (the first failing run, the 2nd in a row, then every even count), when a sub-agent returns `FAIL`, `BLOCKED` or another red word, or when a red result is sent back, and returns to normal when the trouble is resolved. A raised level also comes home after `struggleDecay` requests without a new tripwire. A return is read from a file read (`Read`, or a shell call that only reads), never from a program's output. The judge is off by default: on 258 recorded tripwires a Haiku judge could not tell trouble that continues from trouble that ends, and raising one step at every tripwire beat every judge variant (replay loss 0.283 against 0.517). Turn it on (`judge`, or `effortControl.judge: on`) and one cheap call per tripwire, never awaited, estimates the chance the trouble continues; the effort rises only at `judgeRaiseAt` or above. Agents also get `effort_up`, `effort_down` and `effort_auto` tools: a steered agent moves its own effort, and the level it picks holds over every automatic rule until `effort_auto` returns it to its launch level; any other is refused, the main chat by the name of its own effort control. The main chat is never steered here: its requests go at the effort they carry, and its effort belongs to [auto-effort](https://github.com/rezzminator/auto-effort). Every decision is written to a per-session JSONL log.

It requires function hooks enabled (`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`) and is tested on Claude Code 2.1.283. Install it with `/plugin install effort-live-control@effort-live-control` after `/plugin marketplace add rezzminator/effort-live-control`. Remove it with `claude plugin uninstall effort-live-control@effort-live-control`. The full documentation lives in the repository: https://github.com/rezzminator/effort-live-control

## Options

Set under the plugin's settings, or in the environment variable named in the table. A variable wins over the plugin's setting, which wins over the default; an unset or blank variable counts as not set. Write a boolean as `1`, `0`, `true` or `false` (any case), a list as a JSON array of strings (`[]` is the empty list). A bad value is reported by name at the first hook and the default used.

| Option | Environment variable | Default | What it does |
| --- | --- | --- | --- |
| `floor` | `EFFORT_LIVE_CONTROL_FLOOR` | `medium` | Lowest effort a steered agent is sent. `effortControl.floor` overrides it. |
| `ceiling` | `EFFORT_LIVE_CONTROL_CEILING` | `xhigh` | Highest effort a steered agent is sent. `effortControl.ceiling` overrides it. |
| `parentTag` | `EFFORT_LIVE_CONTROL_PARENT_TAG` | `honor` | `honor`: a tag on the Agent prompt wins over the `effort:` of the agent's definition, and a steered agent starts at the tag held within its floor and ceiling. `ignore`: the definition's `effort:` keeps and the tag is ignored. `effortControl.parentTag` overrides it. |
| `models` | `EFFORT_LIVE_CONTROL_MODELS` | `claude-opus-5-5`<br>`claude-fable-5-1`<br>`claude-sonnet-5-5` | Model id prefixes that are steered; `claude-opus-5-5` also matches `claude-opus-5-5[1m]`. Any other model passes untouched. |
| `judge` | `EFFORT_LIVE_CONTROL_JUDGE` | `false` | Ask the judge at a tripwire; off raises one step mechanically. `effortControl.judge` overrides it. |
| `judgeRaiseAt` | `EFFORT_LIVE_CONTROL_JUDGE_RAISE_AT` | `25` | With the judge on: a probability (0 to 100) at or above this raises the effort one step; below it the effort holds. |
| `tripwires` | `EFFORT_LIVE_CONTROL_TRIPWIRES` | `fail1,fail2,red,redispatch` | The armed tripwires, comma-separated: `fail1` (the first failing test run), `fail2` (the 2nd in a row, then every even count), `red` (a sub-agent returned red), `redispatch` (a red result sent back). ## Logs

Error-level diagnostics appear on screen and in `errors.jsonl`. Warnings and routine effort-change diagnostics go only to `warnings.jsonl` and `info.jsonl` under `$PLUGIN_LOG_DIR/effort-live-control/`, or `$HOME/.local/state/effort-live-control/logs/` when `PLUGIN_LOG_DIR` is unset. If no log directory resolves or writes fail, every unwritten warning and info message falls back to the screen. The logger's own failure notice stays visible, once per failing streak, re-armed by a successful write.

Recoverable model fallbacks remain warnings. Invalid settings and failures that disable pinning, steering, judgment, definition lookup, decision logging or tool registration are errors. Effort-change announcements in tool-result context, button replies and spawn refusals are product output, not diagnostics, and are unchanged.
